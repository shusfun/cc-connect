# CC-Connect 项目经验路由

目标不是执行固定流程，而是让当前任务复用仍然有效的项目经验，并以更少的操作取得足够证据。

## 建立当前状态

- 以用户最新要求、排除项和验收目标定义本次契约。
- 读取 branch、SHA、工作树状态和本次增量。现有 dirty 内容属于用户，后续调查、格式化和验证都不得覆盖它。
- 从当前代码定位权威定义、生产者、边界和消费者。历史路径、Note 和 ADR 只有经过当前代码与版本核验后才能参与决策。

## 选择相关知识

只读取能改变下一步决策的知识所有者，不遍历全部材料：

- `core/`、agent、platform、Web 或共享契约：先读当前实现与根 `AGENTS.md`；涉及版本或兼容时再读 `docs/decisions/2026-08-27-versioning-and-compatibility.md`。
- 文中旧工作区聊天组件仍存在且任务命中其契约时，读取 `docs/decisions/2026-08-23-unified-workspace-chat.md`；组件已替换或正在过渡时，不得用该决定或 `docs/history/` 推断当前实现。
- control、Runtime、deploy-host、容器或激活事务：读取 `docs/decisions/2026-08-24-control-runtime-deployment.md` 和与目标环境对应的部署手册。
- Signed Release、Docker 构建输入或部署安装失败：在 workflow 与当前脚本之外，读取 `.agents/notes/release-deployment-efficiency.md`；先核验其失效条件。
- CI、Release、部署或服务的当前状态来自平台或服务的实时接口，不能从 Note 的历史 run 推断。

## 决定下一项操作

根据当前证据比较候选动作：

- 它能消除哪项仍然存在的不确定性，或覆盖哪个尚未满足的验收目标；
- 是否已有日志、结果、缓存、构建产物或等价信号可复用；
- 墙钟时间、设备成本、外部运行次数以及是否需要额外授权；
- 失败后是否仍能明确缩小根因或影响范围。

选择当前信息收益最高的一项，不预先把日志、静态分析、测试、构建、浏览器和真实入口组成套餐。已有运行故障先从同环境的请求、日志、状态或健康信号中选择能区分假设的一项；静态错误、新功能和外部状态再按各自证据缺口选择，不机械套用同一顺序。

全仓测试、race、生产构建、浏览器、远端 CI 或 Release 只有在仍存在对应独立风险时才进入候选；执行前明确该风险。已有证据已经覆盖时直接复用。

取得结果后重新评估下一项操作或停止。最新验收目标已经满足时，不因旧计划、历史 Note 或 PR 模板继续追加验证。

## 回写经验

- 只有经过复验、可跨任务复用并能改变未来选择的路径才更新知识所有者。
- 架构不变量进入 ADR，当前操作方式进入部署手册，经验性信号与高收益路径进入已有 Agent Note，机械约束进入脚本或 CI。
- 不把未提交架构、单次通过数量、耗时流水账、当前任务授权、候选优化或暂时可用的本机路径写成稳定能力。
