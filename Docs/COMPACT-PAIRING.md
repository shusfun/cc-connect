# 紧凑配对协议 RDX2

二维码格式为 `RDX2:` 加固定顺序 JSON 数组 `[relayOrigin, invitation, deviceIdentityPublicKey]`。邀请保留 32 字节随机数的 base64url 编码，身份保留完整 32 字节 Ed25519 公钥的标准 Base64 编码；不对整个 JSON 再编码。默认地址下为 119 字节，二维码纠错等级 M。设备备注、平台、账号、实例、会话和有效期不进入二维码。

## 配对状态与信任边界

1. Bridge 生成邀请与紧凑文本。Mac／Windows 直接消费 `qrText`，同一内容缓存图像；倒计时不刷新邀请。过期后由用户刷新，经父进程控制管道通知运行中的 Bridge，不重启任务进程。
2. iPhone 仅解析 RDX2。旧 JSON、RMX1 和旧短码明确要求更新，不走旧解析回退。手动输入同样粘贴完整 RDX2 配对码。
3. 手机向 `POST /v1/access/pairing/preview` 的正文提交邀请。预览检查限流、有效期、设备／账号状态及电脑在线状态，禁止缓存；不消费邀请、不创建授权。
4. 手机先比对预览返回的完整公钥与扫码公钥，再显示备注、平台、完整 SHA-256 指纹及有效期。用户确认后才 claim，等待电脑批准，随后 redeem。
5. 授权成功后获取会话地址，再保存可信设备并连接。二维码固定的公钥继续约束 E2E 握手；预览成功不等于配对成功。页面取消或切换设备后丢弃旧异步响应。

服务器地址统一规范为 WSS origin，会话统一连接 `/relay/{sessionId}`；接受原配置中的 `/relay` 尾缀并规范化，拒绝其他路径、查询参数、凭据和非安全协议。首次连接和可信重连使用同一规则。

## 显示、相机与诊断

Mac 默认约 300pt，固定白底黑码、完整留白及整数像素绘制。Windows 同样使用 M 纠错和整数模块。旧短码不再展示。只有当前 Bridge 的有效在线邀请可作为可用二维码显示。

iPhone 使用后置相机、连续对焦／曝光、限定扫描区域、点按对焦和手电筒。识别、加载详情、等待电脑确认、连接及加密握手分阶段反馈；成功识别只触发一次。相机就绪后的识别时间与网络／人工确认时间应分别统计。

WebSocket 路径、鉴权、维护和网络错误使用稳定错误码及诊断请求 ID；不得记录邀请、二维码、Token、原始会话标识或正文。运行中网络断开不结束本地 Codex 任务。

## 验证边界

固定测试样本：旧完整 JSON 445 字节、81×81 模块；新码 119 字节、45×45 模块，均为 M 纠错。同一内容重复编码和生成图案 1,000 次检查一致性。此模块比较是测试样本，不代表所有自定义域名和公钥字符串均使用相同二维码版本。

iPhone 新解析器已通过直接编译生产 Foundation 源码的测试，UI 源码语法检查不等于完整 iOS 构建。iPhone 15 Pro Max 秒扫 p95、真实首次配对／可信重连及加密 RPC 必须用新版 IPA 真机验证，不能以服务器健康检查代替。Windows 同样需要原生构建和设备证据。
