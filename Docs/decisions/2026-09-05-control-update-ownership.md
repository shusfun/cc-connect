# 管理界面与更新事务的所有者

## 问题

旧页面只有拼接表单，缺少个人中心与管理视图；业务容器没有更换自身的权限。让网页直接控制 Docker 会把公开管理接口与高权限执行绑在一起。

## 决定

React、React Router 与 Tailwind CSS v4 只产出静态资源，Relay 拥有账号、会话、权限与 SQLite 管理数据。Mac 保持 SwiftUI 和钥匙串宿主，改为独立窗口；菜单栏不再承载完整管理表单。

独立执行器拥有版本验证、备份、容器替换和恢复事务；业务容器通过认证 Unix Socket 提交固定动作。执行器拥有 Docker 权限，隔离不等于消除宿主风险。只接受固定 GitHub 工作流身份签发的正式发布清单和镜像 digest。

## 被考虑的替代方案

保留原生 JS 不利于复杂管理页面维护；内嵌网页 Mac 界面会增加原生权限桥接。用户选择 React 后台与定制 SwiftUI。单容器配合手动 SSH 可以保持较小权限面，但用户选择网页确认更新和独立执行器。

## 事务与兼容

更新时冻结写入、停止业务并保存一致性备份。新服务健康检查后保存 Compose digest，再提交并解除维护。提交后不能自动恢复旧库；历史恢复撤销旧会话与设备权限。旧密码仍能验证，新设密码使用统一大小写策略。旧单容器部署不自动收编，须单独迁移。

## 验证

测试覆盖版本筛选、签名身份约束、容器归属、端口约束、备份完整性、历史恢复撤销权限和健康失败回滚。Linux Docker、真实发布签名链及客户端 E2E 必须另行验收，不能由本地测试替代。
