# 本地扫码与透明配对

## 页面契约

build 132 将本地二维码识别与 VPS 验证分开。本地 RDX2 格式校验通过后立即震动、停止相机并进入配对确认页，展示服务器地址和二维码公钥的身份指纹。名称、平台和确认按钮等待服务器验证；离线或超时不会把用户退回相机。

`ContentView` 持有 `PairingFlowModel`。页面模型负责草稿、任务取消、请求世代与诊断；既有 `ContentViewModel`／`CodexService` 仍负责配对与连接。只有服务端返回匹配的授权后才保存凭据，加密握手和协议初始化完成后才显示成功。确认页持续保留到用户选择进入工作区。

停止后重扫可以立即验证下一张码，但下一次提交须等待旧连接任务完成取消清理，避免两个连接争用同一个服务。取消、保存授权与连接成功之间均检查当前请求世代；迟到结果不发布到新页面。邀请过期、身份不匹配和无效响应分别分类，不混成同一个错误。

## 诊断与隐私

诊断默认展开，包含实际阶段、单调时钟耗时、版本、build、源码 SHA、设备型号、相机输出状态、元数据计数、连接尝试次数，以及配对 HTTP 请求的接口、状态、错误分类与服务端 requestId。正在发送和等待响应的请求也会显示；未收到响应时不会伪造 HTTP 状态。

每次新码生成独立 operationId，复用后端已有 `x-remodex-operation-id` 支持。二维码、邀请、Token、Cookie、私钥、完整公钥、业务会话、原始响应正文和本地路径不写入诊断。请求路径为固定枚举，服务端错误码使用允许清单。复制的 JSON 最多 200 条／64 KiB，只进入本机剪贴板并在五分钟后过期；不会自动上传或持久保存。审批等待合并计数并保留最近 requestId。

预览请求上限 15 秒。首次配对仍使用既有有期限的审批等待：每次请求完成后间隔三秒，最多检查 100 次，单次请求上限 15 秒。申请结果不确定时禁止自动重复提交；停止等待只取消客户端任务，不冒充撤销了服务器申请。

## 相机所有权

所有相机配置、启停、对焦和手电筒操作进入同一串行队列。新会话启动前停止旧会话，不积累待启动列表。完整图像参与 QR 识别，显示框不裁剪识别范围；一帧多个码优先选择 RDX2。系统中断恢复每次前台周期最多自动重建一次，手动重试重置预算；零 QR 回调本身不触发重启。

## 验证入口

- `bash CodexMobile/scripts/test-pairing-qr.sh`：使用当前 Mac 生成器和 Vision 解码，覆盖两种配对内容、300／600 像素渲染；不使用真实邀请。
- XCTest：`QRScannerPairingValidatorTests`、`PairingFlowTests`；UI：`LocalizationUITests/testLocalPairingPageDoesNotWaitForServer` 和 `testTimeoutStaysOnPairingPageWithDiagnostics`。UI 夹具使用真实生产页面与注入的延迟／失败请求，不触及生产 VPS。
- iOS Actions 先运行上述专项，再执行既有完整测试。专项失败不导出 IPA；完整测试失败仍保留诊断候选包与 failure 结论，正式发布门禁不放宽。
- 专项通过后，仅卸载该 runner 模拟器里的 Remodex 测试 App，再由完整测试重新安装，隔离中文 UI 夹具写入的语言偏好；不删除测试或改写英文断言，不影响真实设备数据。

必须另行完成用户 Pro／Pro Max 真机 30 次扫码和至少 20 次前后台／重开验收。生成图、模拟器和手动输入不替代真机性能证据。这轮不修改 VPS、不改变 RDX2、不接入 SSE／WebRTC，不能据此宣称上述迁移或真机扫码已经验收。
